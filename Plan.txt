==================================================
1. PRODUCT VISION
==================================================

Problem:
AI projelerinde kullanılan ince ayar (Fine-Tuning), RAG ve değerlendirme veri setleri;
- Dağınık Excel, CSV ve bozuk JSONL dosyalarında
- PDF belgelerinde ve ham metinlerde
- Notion / Confluence sayfalarında
- Farklı Git repolarında

kontrolsüz şekilde tutulmaktadır.

Bu durum;
- Veri tekrarına (Duplicates) ve semantik çelişkilere
- Sürüm karmaşasına ve kaybolan veri geçmişine (Lost Lineage)
- Token limitlerinin kontrolsüz aşılmasına ve Out-Of-Memory (OOM) eğitim çökmelerine
- Model formatlarına bağımlı kalmaya (OpenAI, Anthropic, Llama format karmaşası)
- PII (Kişisel veri, API anahtarı, şifre) sızıntılarına

sebep olmaktadır.

Amaç:
AI eğitim ve değerlendirme verilerini oluşturmak, zenginleştirmek, doğrulamak, tokenize etmek, PII temizliğinden geçirmek, sürümlemek ve hedef model mimarisine göre kayıpsız dönüştürmek için tasarlanmış; tamamen yerel (offline-first, zero-cloud dependency) ve yüksek performanslı bir masaüstü stüdyo geliştirmek.

==================================================
2. CORE PRINCIPLES
==================================================

1. Dataset First, Model Second (Model geçicidir, veri setiniz kalıcı varlığınızdır).
2. Internal Format != Model Format (Dahili yapı modelden bağımsız, evrensel şemada tutulur).
3. Export-Time Transformation (Veri ham saklanır, dışa aktarılırken modele dönüştürülür).
4. Full Data Lineage & Auditability (Her satırın nereden geldiği, kimin düzenlediği ve onayladığı bilinir).
5. Dataset Quality > Training Method (Veri kalitesi en iyi optimizasyon algoritmasından üstündür).
6. Zero-Telemetry & Offline-First (Kullanıcı verisi cihazdan asla izinsiz çıkmaz).
7. Portable Project Files (.aids / SQLite bazlı taşınabilir proje dosyaları).
8. Extreme Virtualization (100.000+ kayıtta 60 FPS akıcı liste ve arama performansı).

==================================================
4. DATASET TYPES & UNIFIED SCHEMAS
==================================================

Tüm kayıt tipleri veritabanında esnek, indekslenebilir ve tip güvenli JSON Payload olarak tutulur.

1. Instruction Dataset (SFT, LoRA, QLoRA, DoRA, Full Fine-Tune)
   Payload:
   {
     "instruction": "Kullanıcıya talimatı...",
     "input": "Opsiyonel bağlam / kaynak metin...",
     "output": "Beklenen model yanıtı..."
   }

2. Chat Dataset (Multi-turn Konuşmalar)
   Payload:
   {
     "system_prompt": "Opsiyonel sistem rolü...",
     "messages": [
       { "role": "user", "content": "Merhaba!" },
       { "role": "assistant", "content": "Nasıl yardımcı olabilirim?" }
     ]
   }

3. Preference Dataset (DPO, ORPO, RLHF, KTO)
   Payload:
   {
     "prompt": "Girdi sorusu...",
     "chosen": "Yüksek kaliteli, tercih edilen yanıt...",
     "rejected": "Düşük kaliteli, reddedilen yanıt..."
   }

4. Tool Calling / Agent Dataset (Function Calling)
   Payload:
   {
     "prompt": "İstanbul'da hava nasıl?",
     "tools": [ { "name": "get_weather", "description": "Hava durumu servisi", "parameters": { ... } } ],
     "tool_calls": [ { "name": "get_weather", "arguments": { "city": "Istanbul" } } ],
     "tool_output": "{ \"temp\": 22, \"condition\": \"Sunny\" }",
     "final_response": "İstanbul'da hava şu anda güneşli ve 22 derecedir."
   }

5. Evaluation & Benchmark Dataset
   Payload:
   {
     "question": "Değerlendirme sorusu...",
     "expected_answer": "Beklenen referans cevap...",
     "rubric": "Puanlama kriterleri...",
     "score": 5
   }

6. Classification Dataset
   Payload:
   {
     "text": "Sınıflandırılacak metin...",
     "label": "Sentiment_Positive"
   }

7. RAG Test Dataset
   Payload:
   {
     "question": "Doküman bazlı soru...",
     "expected_document_ids": ["doc_123", "chunk_45"],
     "expected_answer": "Doğru yanıt..."
   }

==================================================
5. DATASET RECORD (DATA MODEL & METADATA)
==================================================

DatasetRecord Alanları:
- Id: Guid (Primary Key)
- DatasetId: Guid (Foreign Key)
- Type: DatasetType (Enum: Instruction, Chat, Preference, ToolCalling, Evaluation...)
- Status: RecordStatus (Draft, InReview, Approved, ExportReady, Archived)
- DataPayload: string (JSON - SQLite JSON1 & EF Core Complex Type)
- TokenCount: int (Hesaplanmış toplam token)
- InputTokenCount: int
- OutputTokenCount: int
- Metadata: string (JSON - Key-Value serbest meta veriler)
- Tags: List<string> (Hızlı etiketleme)
- Lineage: RecordLineage (Value Object: CreatedBy, Source, AIModel, PromptHash)
- CreatedAt: DateTimeOffset (UTC)
- UpdatedAt: DateTimeOffset (UTC)

==================================================
6. RECORD LIFECYCLE & SPEED-TAGGING UX
==================================================

Kayıt Durumları:
Draft ➔ InReview ➔ Approved ➔ ExportReady ➔ Archived

Seri Düzenleme & İnceleme UX (Speed-Review):
- Klavye Kısayolları Odaklı Arayüz:
  * Ctrl + Enter: Onayla (Approved) ve sonraki kayda geç.
  * Ctrl + Backspace: Reddet / Arşivle ve sonrakine geç.
  * Alt + 1..5: Hızlı Durum / Tag atama.
- Split-View / Yan Yana Düzenleme: Sol tarafta sanallaştırılmış liste, sağ tarafta seçili kaydın zengin editörü.
- Markdown & Code Highlighting: AvaloniaEdit ile JSON, Python, Markdown sözdizimi renklendirmesi.
- Preference (DPO) Diff View: Chosen ve Rejected metinleri arasındaki farkları renkli (kırmızı/yeşil) gösteren görsel diff bileşeni.

==================================================
7. ADVANCED SEARCH & FILTER ENGINE
==================================================

Yüz binlerce kayıt arasında anlık sorgulama motoru:
- SQLite FTS5 (Full-Text Search) İndeksi: Başlık, girdi, çıktı ve konuşma metinlerinde milisaniyeler içinde arama.
- Yapısal Filtreleme (Filter Chips / Query Builder):
  * Status bazlı (örn: Yalnızca "InReview")
  * Token aralığı (örn: TokenCount > 4096 veya TokenCount BETWEEN 500 AND 1500)
  * Tag & Kategori bazlı
  * AI Üretimi bazlı (GeneratedByAI == true)
  * Kalite Skoru / Hata Filtresi (Yalnızca "Duplicate" veya "Missing Output" olanlar)

==================================================
8. TOKEN & CONTEXT ENGINE
==================================================

Out-Of-Memory (OOM) ve context kırpılmasını önleyen yerel tokenizasyon:
- Yerel Kütüphaneler: Microsoft.ML.Tokenizers / Tiktoken-CSharp (Sıfır internet ihtiyacı).
- Desteklenen Kodlamalar:
  * cl100k_base (OpenAI GPT-4 / GPT-3.5)
  * o200k_base (OpenAI GPT-4o)
  * Llama-3 BPE (8k / 128k context)
  * Mistral & Gemma SentencePiece
- Analiz & Görselleştirme:
  * Kayıt bazlı Input / Output / Toplam token sayısı rozeti.
  * Context Window Eşik Uyarıları: 2048, 4096, 8192, 16k, 32k, 128k sınırını aşan kayıtları vurgulama.
  * Token Dağılım Histogramı: Veri setinin token yoğunluk grafiği.
  * API Fine-Tuning Maliyet Tahmini (OpenAI / Anyscale güncel fiyat katsayıları ile).

==================================================
9. DATASET HEALTH & QUALITY ENGINE
==================================================

Dataset Kalite Skoru (0 - 100) ve Otomatik Temizlik:
- Duplicate Detection: Birebir MD5/SHA-256 hash çakışmaları.
- Semantic & Near-Duplicate Detection: MinHash / Jaccard / Levenshtein benzerlik eşiği (örn: %90+ benzer sorular).
- Boş / Eksik Veri Analizi: Boş instruction, eksik yanıt, tek taraflı konuşmalar.
- Anomali Tespiti: Aşırı kısa yanıtlar ("ok", "evet"), girdiyle birebir aynı yanıtlar.
- Markdown / Syntax Doğrulama: Kapanmamış kod blokları (```), geçersiz JSON veya HTML yapıları.
- Consistency Check: Benzer girdilere verilen çelişkili veya zıt yanıtlar.
- Tek Tıkla Temizleme (Auto-Cleaner): Yinelenenleri silme, boşlukları kırpma, geçersiz kayıtları arşivleme.

==================================================
10. PII & SENSITIVE DATA SCRUBBER (YENİ / GİZLİLİK)
==================================================

Model eğitim verisine şirket sırrı veya kişisel veri sızmasını önleyen maskeleme motoru:
- Yerel Kural & Regex Tabanlı Tarama:
  * E-posta Adresleri (örn: test@company.com ➔ [EMAIL])
  * Telefon Numaraları (➔ [PHONE])
  * T.C. Kimlik / Sosyal Güvenlik / Kimlik Numaraları (➔ [ID_NUMBER])
  * Kredi Kartı Numaraları (Luhn algoritması doğrulamalı ➔ [CREDIT_CARD])
  * IP Adresleri ve Dahili URL'ler (➔ [INTERNAL_IP] / [URL])
  * API Anahtarları, Token'lar ve Gizli Şifreler (OpenAI sk-..., AWS AKIA..., Bearer token vb. ➔ [API_KEY])
- Özelleştirilebilir Sözlük / Blacklist: Şirket veya kişi isimleri için özel sansür kuralları.
- Önizleme ve Geri Alınabilir Maskeleme Modu.

==================================================
11. TRAIN / VALIDATION / TEST SPLIT & STRATIFICATION
==================================================

Eğitim için bilimsel ve dengeli veri bölme:
- Oransal Bölme (Split Presets):
  * %80 Train / %10 Validation / %10 Test
  * %90 Train / %10 Validation
  * Özel yüzdelik dilim belirleme
- Stratified Sampling (Tabakalı Örnekleme):
  * Belirli etiketlerin (Tags) veya kategorilerin train ve test setlerine eşit dağıtılmasını sağlama.
- Reproducibility (Rastgelelik Tohumu - Random Seed):
  * Aynı seed (örn: Seed=42) kullanıldığında her zaman birebir aynı split dosyasının üretilmesi garantisi.
- Export Entegrasyonu: Tek tıkla `train.jsonl`, `val.jsonl`, `test.jsonl` olarak ayrı ayrı dışa aktarma.

==================================================
13. EXPORT SYSTEM (TARGET TEMPLATES)
==================================================

Felsefe: Tek bir veri seti kaynağından istenilen her modele anında dönüştürme.

Desteklenen Formatlar:
- OpenAI JSONL (Fine-tuning messages formatı: {"messages": [...]})
- ShareGPT JSON / JSONL (conversations formatı: [{"from": "human", "value": ...}])
- ChatML Format (<|im_start|>system...<|im_end|>)
- Alpaca Format ({"instruction": ..., "input": ..., "output": ...})
- Llama 3 Instruct Format (<|begin_of_text|><|start_header_id|>...)
- Mistral / Gemma Format
- HuggingFace DPO Format ({"prompt": ..., "chosen": ..., "rejected": ...})
- Unsloth & Llama-Factory uyumlu Dataset JSON ve konfigürasyon şablonları.

Export Seçenekleri:
- Durum Filtresi: Yalnızca "Approved" veya "ExportReady" kayıtları alma seçeneği.
- Token Filtresi: Belirlenen context uzunluğunu (örn: > 4096) aşanları export dışı bırakma.
- PII Maskeleme: Export anında hassas verileri otomatik maskeleme seçeneği.
- Train / Val / Test split olarak ayrı dosyalara kaydetme.

==================================================
14. VERSIONING & SNAPSHOT SYSTEM
==================================================

- Semantic Versioning (v1.0.0, v1.1.0, v2.0.0).
- Git Mantığında Immutable Snapshots:
  * Her versiyonda 100k kaydı kopyalamak yerine "RecordVersionMapping" tablosunda durum dondurma.
- Diff & Compare: İki versiyon arasında eklenen (+), silinen (-) ve güncellenen (~) kayıtların görsel karşılaştırması.
- Rollback: İstenilen versiyon durumuna güvenle dönebilme.
- Dondurulmuş Versiyonlar (Frozen/Read-Only): Eğitime gönderilmiş bir versiyonun kaza eseri değiştirilmesini engelleme.

==================================================
15. DATASET ANALYZER & TRAINING ADVISOR
==================================================

Dataset yapısına göre eğitim rehberliği:
- Kayıt Sayısı & Çeşitlilik Puanı.
- Önerilen Fine-Tuning Metotları:
  * < 1.000 kayıt: Few-Shot In-Context Learning veya LoRA
  * 1.000 - 10.000 kayıt: QLoRA / LoRA (Rank 16-64)
  * 10.000+ kayıt: DoRA veya Full Parameter Fine-Tune
- Donanım İhtiyaç Tahmini:
  * 7B, 14B, 70B model boyutlarına göre önerilen GPU VRAM (16GB, 24GB, 48GB, 80GB)
  * Tahmini LoRA adapter boyutu (MB)

20. ARCHITECTURE DECISION RECORDS (ADR)
==================================================

ADR-001: SQLite WAL Mode & .aids Proje Formatı (Yerel, taşınabilir, tek dosya veritabanı).
ADR-002: Avalonia UI 11+ (.NET 9, cross-platform, yüksek performanslı XAML masaüstü arayüzü).
ADR-003: Model Bağımsız Dahili Depolama (Unified JSON Schema & EF Core JSON columns).
ADR-004: Export Zamanı Model Dönüşümü (Dahili veriyi koruyarak hedef modele kayıpsız adaptasyon).
ADR-005: Clean Architecture & CQRS (Domain, Application, Infrastructure, Desktop ayrımı).
ADR-006: Data Virtualization (100k+ kayıtta UI donmasını engelleyen sanallaştırma).
ADR-007: Yerel Tokenizasyon Motoru (Tiktoken ile API bağımsız token ve maliyet hesabı).
ADR-008: PII & Veri Gizliliği Önceliği (Zero-telemetry ve çevrimdışı çalışma garantisi).
ADR-009: Tekrarlanabilir Split Mekanizması (Seed tabanlı deterministik Train/Val/Test bölme).
