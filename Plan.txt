--------------------------------------------------
1. PRODUCT VISION
--------------------------------------------------

Problem:

AI projelerinde kullanılan veri setleri;

- Excel dosyalarında
- JSON ve JSONL dosyalarında
- PDF belgelerinde
- Notion sayfalarında
- Confluence alanlarında
- Git depolarında

dağınık şekilde tutulmaktadır.

Bu durum;

- veri tekrarına (duplicates)
- sürüm karmaşasına
- token limitlerinin aşılmasına (OOM hataları)
- kalite kaybına ve tutarsız formatlamaya
- model bağımlılığına
- hassas şirket verilerinin (PII, API key) eğitim setine sızmasına

sebep olmaktadır.

Amaç:

AI eğitim verilerini;

- oluşturmak
- düzenlemek ve zenginleştirmek
- sürümlemek (Diff / Snapshot tabanlı)
- tokenize edip context length kontrolünden geçirmek
- kalite kontrolünden geçirmek (Health Engine)
- kişisel/hassas verilerden arındırmak (PII Scrubber)
- farklı modeller için export etmek (OpenAI, ShareGPT, ChatML vb.)

üzere merkezi, yerel (offline-first, zero-cloud dependency), gizliliğe odaklı bir masaüstü uygulama geliştirmek.

--------------------------------------------------
2. CORE PRINCIPLES
--------------------------------------------------

1. Dataset First, Model Second (Model geçicidir, veri seti kalıcı varlıktır)
2. Internal Format != Model Format (Dahili yapı modelden bağımsız tutulur)
3. Export Time Transformation (Veri ham saklanır, modele export anında dönüştürülür)
4. Data Lineage Must Exist (Her kaydın kökeni, tarihi ve onaylayanı bilinir)
5. Dataset Quality > Training Method (Veri kalitesi model parametrelerinden önemlidir)
6. Offline First & Local Privacy (Veriler asla izinsiz dışarı çıkmaz, sıfır telemetri)
7. Portable Project Files (.aids / SQLite bazlı tek dosya taşınabilirliği)
8. Extreme Virtualization (100.000+ kayıtta UI donması olmadan akıcı çalışma)

--------------------------------------------------
9. RECORD LIFECYCLE & SERİ İNCELEME UX
--------------------------------------------------

Akış:

Draft
↓
Review (InReview)
↓
Approved
↓
Export Ready
↓
Archived

Özellikler:
- Toplu Durum Değiştirme (Bulk Status Transition)
- Yalnızca "Approved" veya "Export Ready" durumundakileri export etme filtresi.

Seri Düzenleme & İnceleme UX (Speed-Review):
- Klavye Kısayolları:
  * Ctrl + Enter: Onayla (Approved) ve sonraki kayda geç.
  * Ctrl + Backspace: Reddet / Arşivle ve sonrakine geç.
  * Alt + 1..5: Hızlı Durum / Tag atama.
- Split-View: Sol tarafta sanallaştırılmış liste, sağ tarafta seçili kaydın zengin editörü.
- Markdown & Code Highlighting: AvaloniaEdit ile sözdizimi renklendirmesi.
- Preference (DPO) Diff View: Chosen ve Rejected metinleri arasındaki farkları renkli gösteren diff paneli.

--------------------------------------------------
13. TOKEN & CONTEXT ENGINE
--------------------------------------------------

Amaç: Out-of-Memory (OOM) ve context kırpılmasını önlemek.

Özellikler:
- Yerel Tokenizer Kütüphaneleri (Microsoft.ML.Tokenizers, Tiktoken-CSharp)
- Desteklenen Kodlamalar:
  * cl100k_base (OpenAI GPT-4 / GPT-3.5)
  * o200k_base (GPT-4o)
  * Llama-3 BPE (8k / 128k context)
  * Gemma / Mistral SentencePiece
- Analiz ve Raporlama:
  * Satır bazında Input / Output / Toplam Token hesabı
  * Context Window Aşım Uyarıları (2048, 4096, 8192, 16k, 32k, 128k sınırlarını geçenleri filtreleme)
  * Token Dağılım Histogramı (Görsel token yoğunluk grafiği)
  * Tahmini Eğitim Maliyeti (Fine-tuning API maliyet hesabı)

--------------------------------------------------
14. DATASET HEALTH ENGINE & QUALITY SCORING
--------------------------------------------------

Amaç:

Dataset Quality Score (0-100) üretmek ve temizleme sihirbazı sunmak.

Kontroller:

- Duplicate Detection (Exact Hash MD5/SHA256 eşleşmeleri)
- Similarity Detection (MinHash / Jaccard / Levenshtein veya yerel Embedding)
- Missing Data Detection (Boş instruction, boş yanıt vb.)
- Metadata Validation
- Tag Validation
- Consistency Analysis (Aynı veya benzer soruya zıt yanıt tespiti)
- Token Anomaly Detection (Aşırı kısa veya aşırı uzun yanıtlar)
- Leakage / Repetition Check (Cevabın girdi içinde birebir tekrar etmesi)
- Markdown & JSON Validation (Kapanmamış kod blokları, bozuk JSON yanıtları)

Çıktı:

- Health Score: 0-100
- Tek Tıkla Temizleme (Auto-Fix) Sihirbazı

--------------------------------------------------
15. PII & SENSITIVE DATA SCRUBBER
--------------------------------------------------

Amaç: Kişisel veya gizli verilerin eğitim setine girmesini engellemek.

Kontroller & Maskeleme:
- E-posta Adresleri (örn: test@company.com ➔ [EMAIL])
- Telefon Numaraları (➔ [PHONE])
- T.C. Kimlik / Kimlik Numaraları (➔ [ID_NUMBER])
- Kredi Kartı Numaraları (Luhn algoritması doğrulamalı ➔ [CREDIT_CARD])
- IP Adresleri ve Dahili URL'ler (➔ [INTERNAL_IP] / [URL])
- API Anahtarları ve Secret Token'lar (OpenAI sk-..., AWS, Bearer token ➔ [API_KEY])
- Özel Yasaklı Kelime Sözlüğü (Blacklist)

--------------------------------------------------
16. TRAIN / VALIDATION / TEST SPLIT & STRATIFICATION
--------------------------------------------------

Eğitim için bilimsel ve dengeli veri bölme:

- Oransal Bölme (Split Presets):
  * %80 Train / %10 Validation / %10 Test
  * %90 Train / %10 Validation
  * Özel yüzdelik dilim belirleme
- Stratified Sampling (Tabakalı Örnekleme):
  * Belirli etiketlerin (Tags) veya sınıfların train ve test setlerine eşit dağılması
- Reproducibility (Random Seed):
  * Aynı seed kullanıldığında birebir aynı bölmenin üretilmesi
- Export Entegrasyonu: Tek tıkla train.jsonl, val.jsonl, test.jsonl olarak ayrı dosyalara yazma

--------------------------------------------------
17. ADVANCED SEARCH & FILTER ENGINE
--------------------------------------------------

- SQLite FTS5 (Full-Text Search) İndeksi: Girdi, çıktı ve konuşma metinlerinde milisaniyede tam metin arama.
- Filtreleme Kriterleri:
  * Status bazlı (InReview, Approved vb.)
  * Token aralığı (örn: TokenCount > 4096)
  * Tag & Kategori bazlı
  * AI Üretimi bazlı (GeneratedByAI == true)
  * Hata / Kalite uyarısı bazlı filtreleme

32. ARCHITECTURE DECISION RECORDS (ADR)
--------------------------------------------------

ADR-001: SQLite (WAL Mode, FTS5, .aids taşınabilir proje dosyası)
ADR-002: Avalonia UI (.NET 9 cross-platform, yüksek performanslı XAML)
ADR-003: Model bağımsız veri saklanacak (Unified JSON Schema)
ADR-004: Export sırasında dönüşüm yapılacak (Export-time transformation)
ADR-005: Plugin mimarisi kullanılacak (IExportProvider, IImportProvider vb.)
ADR-006: Clean Architecture kullanılacak (Domain, Application, Infrastructure, Desktop)
ADR-007: MVVM kullanılacak (CommunityToolkit.Mvvm)
ADR-008: Yerel veri saklama yapılacak (Zero-telemetry, offline-first)
ADR-009: Data Virtualization kullanılacak (100k+ kayıtta akıcı UI performansı)
ADR-010: Yerel Tokenizasyon Motoru (Tiktoken ile API bağımsız token ve maliyet hesabı)
ADR-011: Deterministik Train/Val/Test Split (Seed tabanlı tekrarlanabilir veri bölme)
